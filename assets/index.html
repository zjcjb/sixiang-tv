为什么默认改暖色：家庭观影常在客厅、多人、长时间，冷墨黑 + 高对比金线偏「一个人深夜看片」。暖居把黑位抬成暖棕、主色改琥珀铜、焦点边加粗到 2px（遥控器远距离更易辨认），字距略放宽。低奢仍作为一键可回的皮肤保留，没有丢掉。
浅色皮肤的代价（诚实标注）：上游 Theme.Material3.Dark.NoActionBar，activity_setting.xml 等布局把文字硬编码成 @color/white。晨光原木要逐个覆盖，改动量远大于另外三套，首批建议只上三套深色。

背景图与数据链路

项实测 / 结论
内核已有壁纸机制WallConfig.java + CustomWallView.java；配置顶层 wallpaper 字段由 VodConfig.initWall() 读取；设置页已有 wall / wallUrl / wallDefault / wallRefresh 整组行 —— 背景图这条链路零 Java 改动
当前壁纸值https://picsum.photos/1280/720/?blur=10，随机图、国内可达性不稳，建议换成配置仓库托管
上游自带壁纸app/src/leanback/res/drawable-nodpi/wallpaper_1..4.webp，可直接复用，不必自己画
四张新底图make_skins.py 纯本地 Pillow 程序化生成，1920×1080，共约 68 KB，低对比 + 暗角 + 中心留空，客户端再叠 overlay 才放文字与海报；零网络、零积分、无水印
海报数据沿用 v3：四榜 80 条 + 采集站首页 20 条真实海报；豆瓣 20 张已本地化到 posters/movie/（裸链 418 的坑不重踩）
主题选择 UImobile sourceSet 已有 ThemeDialog.java / ThemeAdapter.java / dialog_theme.xml，TV 端可移植复用，不必从零写

落地路径（分三层，不要一次全塞）

层做法改动
① 背景图把皮肤对应图片推到配置仓库，wallpaper 指向 jsdelivr；或设置页现有 wallUrl 直接填零 Java
② 皮肤切换 UI移植 mobile 的 ThemeDialog 到 leanback；设置页复用一行 → 弹出四张皮肤卡；选择存 SharedPrefs(sixiang_skin)少量 Java + 一个 dialog
③ 配色切换colors.xml / styles.xml 定义 Theme.App.Warm/Lux/Scifi，BaseActivity 在 onCreate 里 setTheme()，切换后 recreate()；同时按皮肤换 wallpaper需要 Java + 资源，部分硬编码 View 只跟随 accent
顺序建议不变：先按 v1 补丁跑通首次云编译、拿到能装的 APK，再叠 ①→②→③。v1 的 17 处 Java 改动还没经过 Gradle，一次全塞报错分不清来源。
